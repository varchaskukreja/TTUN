# Isolated comparison integration prototype

This branch starts at cdc3e36646f6e1729e20fcff4609e4a052370d53. The main worktree, frozen capture/qualification helpers and definition-candidate worktree were not edited. No image build, activation, push, or answer-label evaluation was performed.

The selector exposes `--experimental-comparisons`, disabled by default. Docker packages the evidence and standalone proof helpers, but its CMD is byte-for-byte unchanged. This is an experimental conditional proposal mode, not production authorization; the manifest explicitly records `production_authorized: false`.

Base selection now records whether dependency selection completed or fell back. Every existing fallback-all return has an explicit reason, including missing source/dependencies, invalid syntax, global/test-module effects, changed callable kind, definition/collection effects and failed class import guard. Exceptions leave status unknown. Comparison narrowing requires the exact successful dependency-selection status, so an all-tests set resulting from a fallback cannot be silently overridden. A successful dependency selection covering every test is distinguished from fallback-all.

`ExperimentalComparisons` validates the pinned compressed/expanded hashes, runtime helper and selector hashes, Python minor, exact catalog and original capture audit before using evidence. The artifact is the entire lossless 3.11MB capture. Extraction preserves the original proof and audit functions' ASTs exactly; runtime modules do not import instrumentation, pytest plugins or offline answer-scoring tools.

The proposal uses the exact same whole-patch equal-width Is/Eq text/token/AST gate and observed-type proof. It retains unobserved contexts, source/code-object readers, production source readers, missing/unmapped tests, nonpassing baselines and `baseline_unstable_tests`. Known unstable IDs are added even if absent from the base selection. Unknown unstable IDs fall back to all tests. Unknown evidence contexts, invalid line/read indices, collection readers and malformed metadata block narrowing. Current source hashes are checked by qualification.

Validation: 36 tests pass (12 integration-policy tests and 24 existing selector tests). All 1,671 frozen site-policy decisions equal the original analyzer modulo mandatory unstable retention; 27 sites add previously omitted unstable tests. All 6,684 fallback-policy checks retain every original test. The source proof/audit function ASTs match their frozen origins. No labels were read. The full machine report is `integration-all-sites.json` at the worktree root, with a compact provenance summary in `validation/comparison-integration-prototype.json`.

The all-site comparison uses normalized single-comparison expressions to exercise the actual site observations/readers/context policies; source/hash metadata remains losslessly preserved. This does not make unsupported IsNot/NotEq patches eligible: the real text gate still rejects unequal-width edits. Actual source-bound acceptance and malformed/extra-change rejection are covered by integration unit tests and the earlier 98-file representation validation.

This integration does not discharge warm-order/cold-execution, source/code-reader completeness, downstream shared-state, native activity, dynamic type-slot stability or instrumentation-transparency obligations. Explicit opt-in enables a research experiment under those conditions; it is not permission to ship it. Retention may reduce earlier projected gains.
